Apps are only reachable through Nginx — containers are never directly exposed to the internet. All traffic enters via the load balancer on port 80/443.

6.1 Database & Data Security

1

bcrypt Password Hashing

All passwords stored as bcrypt hashes (cost factor 10). Raw passwords never persisted. Verified via bcrypt.compare() on login — resistant to rainbow table attacks.

2

JWT Stateless Authentication

JWTs signed with JWT_SECRET (env var), expire in 7 days. Every protected route runs verifyToken() middleware — no server-side session storage needed.

3

Input Validation & Sanitisation

Git URLs validated against a strict regex in validators.js. Project names are sanitised (alphanumeric + hyphens only) before use as subdomain slugs — prevents command injection.

Container & Infrastructure Isolation

  • Linux Namespace Isolation: Docker containers run in separate PID, IPC, and Mount namespaces — complete process-level isolation from the host.
  • No Host FS Access: Containers are started without --privileged or host volume mounts; cannot read host filesystem.
  • Kubernetes Resource Limits: Each K8s pod has cpu: 500m and memory: 512Mi limits enforced by the scheduler — prevents denial-of-service from runaway containers.
  • NetworkPolicy (Pod Isolation): k8s/network-policy.yaml denies all inter-pod traffic; only Nginx proxy pods may reach app pods on port 3000/80.
  • Internal Routing Only: Nginx conf.d routes map internal ports; containers are not listed in any external DNS or firewall rule.
