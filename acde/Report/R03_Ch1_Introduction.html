Introduction & Objectives

Project Overview

1.1 Introduction

The Automated Cloud Deployment Engine (ACDE) is a custom Platform as a Service (PaaS) built on Node.js, Docker, Kubernetes, MongoDB, and Nginx. It eliminates manual deployment overhead by transforming a raw Git repository URL into a live, publicly accessible web application — fully automatically.

ACDE handles every step: cloning the source code, detecting the technology stack, generating a Dockerfile if none is present, building a Docker image, running an isolated container, allocating a free host port, writing a dynamic Nginx reverse-proxy route, and returning a live URL — all triggered by a single API call from the dashboard.

1.2 Statement of the Problem

  • Manual Server Provisioning: Developers spend hours configuring environments and resolving dependency conflicts before a single line of code runs in production.
  • Complex Routing Setup: Nginx or Apache reverse-proxy configuration is error-prone and must be repeated for every new application.
  • Lack of Build Visibility: Fragmented, scattered log files make it difficult to diagnose deployment failures in real time.
  • No Isolation: Running applications directly on the host OS creates dependency conflicts and security risks.

1.3 Objectives of the Project

  • Secure Orchestration: Build a Node.js engine that safely executes host-level Docker and Kubernetes daemon commands.
  • Automated Pipelines: Automate the complete lifecycle — clone → build Docker image → spin up isolated container.
  • Scalable Orchestration: Demonstrate Kubernetes-grade scalability with resource limits (CPU 500m, RAM 512Mi) and readiness probes.
  • Dynamic Reverse Proxy: Auto-write Nginx conf.d snippets to route traffic to newly assigned container ports.
  • Centralised Dashboard: Provide a React UI with real-time SSE build-log streaming, deployment health, and system status.

1.4 Project Scope & Applicability

ACDE is designed for individual developers and small teams who need a self-hosted, zero-cost PaaS on an Ubuntu Linux machine. It supports two project types: Node.js applications (auto-detected via package.json) and static HTML sites (auto-detected via index.html). It accepts both public HTTPS Git URLs (GitHub, GitLab, Bitbucket) and local directory paths for offline demos.

Out of scope (v2): GitHub webhook CI/CD, auto-provisioned databases, private repo OAuth, Prometheus monitoring, and production GCP deployment.
