3.3 Data Integrity & Validation Constraints

  • Git URL validation: Regex accepts only GitHub/GitLab/Bitbucket HTTPS+SSH or local paths. Enforced in validators.js before project creation.
  • Project name sanitisation: Strips special characters; max 80 chars; used to generate a safe subdomain slug.
  • Mongoose unique index: email field on Users collection prevents duplicate accounts at DB level.
  • Port uniqueness: Allocator queries live Deployments + probes OS; never assigns an in-use port.
  • Ownership enforcement: Every project route checks project.user_id === req.user._id before proceeding.

3.2 Database Design — MongoDB Collections

CollectionKey FieldsIndexes
users name, email, password_hash, created_at email unique
projects user_id (FK), project_name, git_repo_url, tech_stack, status, updated_at user_id
deployments project_id (FK), subdomain, assigned_port, container_id, image_tag, mode, status, live_url project_id
logs deployment_id (FK), log_message, timestamp deployment_id

All timestamps use Date.now default. Projects and Deployments have a pre('save') hook that updates updated_at automatically.

3.4 User Interface Design

The React + Vite frontend (port 5173) follows a dark-mode SPA layout with the following screens:

Login / Register

JWT auth form. Token stored in localStorage. Auto-redirects to Dashboard on success.

Dashboard

Stat cards (total / deployed / failed). System health badge. Recent 5 projects with live links.

Projects List

All user projects with status pills. New Project form. Click row to open detail.

Project Detail

Deploy / Stop buttons. Real-time SSE build log terminal. Live URL button. Deployment info.
