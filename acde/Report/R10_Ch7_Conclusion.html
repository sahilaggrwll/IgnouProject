7.1 Conclusion

The Automated Cloud Deployment Engine (ACDE) successfully addresses all five stated objectives and demonstrates a fully functional, secure, and observable PaaS pipeline on a standard Ubuntu Linux machine. The system reduces a traditionally multi-hour manual deployment process to a single API call, completing it in under two minutes for most Node.js and static web projects.

All major deliverables — clone pipeline, Docker build automation, dynamic Nginx reverse-proxy, Kubernetes deployment with resource limits, real-time SSE log streaming, JWT-secured REST API, and a React dashboard — were implemented, integrated, and tested.

The project confirms that enterprise-grade deployment automation concepts (containerisation, orchestration, dynamic routing, defence-in-depth security) are achievable with open-source tools at zero cost, making ACDE a viable foundation for a production PaaS targeting student developers and small teams.

Key Accomplishments

Secure Automation

JWT + bcrypt auth; input sanitisation; no shell injection vectors in subprocess calls.

Container Isolation

Linux namespace isolation; no privileged mode; NetworkPolicy for K8s pod segregation.

K8s Scalability

Resource limits, readiness probes, and kubectl apply / docker run dual-mode deployment.

Dynamic Routing

Auto-written Nginx conf.d snippets; OS-level port probe prevents bind collisions.

7.2 Limitations

  • Single-machine only: Current deployment runs on one Ubuntu host; no horizontal scaling or distributed worker nodes.
  • Public repositories only: Git cloning requires a public HTTPS URL; private repos via OAuth or SSH key are not yet supported.
  • No database provisioning: Applications requiring their own PostgreSQL or MySQL instance must set that up externally.
  • Static tunnel URLs: localtunnel public URLs are ephemeral and reset on backend restart; not suitable for permanent production use.
  • Manual Nginx reload: Nginx conf.d writes are automated but actual nginx -s reload requires the host command to be configured in NGINX_RELOAD_CMD.
  • No CI/CD webhooks: Re-deployments must be triggered manually via the dashboard; no automatic rebuild on git push.

7.3 Future Scope & Enhancements (v2.0)

⚡

True CI/CD Integration

GitHub/GitLab webhook listeners to automatically trigger build-and-deploy pipelines on every git push to the configured branch.

🗄️

Auto-Provisioned Databases

Spin up dedicated PostgreSQL or MongoDB containers attached to the app network with auto-injected connection strings via environment variables.

🔑

Private Repository Authentication

OAuth 2.0 (GitHub / GitLab) and SSH key management to clone private repositories and organisations.

📊

Prometheus & Grafana Monitoring

Real-time CPU, memory, and request-latency metrics per container, visualised directly in the user dashboard.
